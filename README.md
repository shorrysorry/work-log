# work-log

프론트엔드 개발자로 일하며 **맡은 문제, 내린 판단, 만든 결과**를 기록하는 곳입니다.
회사의 코드·내부 구조·고객 정보는 기록하지 않습니다 → [작성 규칙](GUIDELINES.md)

## 한눈에 보기

| 항목 | 내용 |
|---|---|
| 기간 | 2022.09 ~ 현재 (4년+) |
| 도메인 | 채용 SaaS (B2B) |
| 맡은 제품 표면 | 백오피스 · 채용 사이트 · 지원자 메시징 · 브라우저 확장 · 데스크톱 앱 · 공통 UI |
| 주요 기술 | React · Next.js · TypeScript · Electron · Vitest · Playwright · Claude Code · Codex |

## 세 가지 축

| 축 | 내용 |
|---|---|
| [**제품 개발**](product/) | 채용 SaaS의 어떤 서비스에 무엇을 만들고 고쳤는지 — 서비스 영역별 정리 |
| [**AX 전환**](ax/) | AI 개발 하네스 개발·Codex 이식, AI를 실무 흐름(스펙 검증·리뷰)에 적용한 일 |
| [**개발 프로세스**](process/) | PRD 구조 개선, 구현 전 스펙 리뷰, 코드 리뷰·통합·릴리즈, 팀 운영 |

### 하이라이트

- **제품 개발** — 채용 운영·지원자 관리·외부 서비스 연동·데이터 보호까지 채용 흐름 전반의 프론트엔드. 커밋 약 5,200개 · MR 118건 · 릴리즈 항목 담당 56건
- **AX 전환** — 팀 AI 개발 하네스를 Codex로 이식(skill 27개), 디자인 근거 검증 게이트 추가. 2026년 하반기 커밋의 76%를 AI와 함께 작성
- **개발 프로세스** — PRD 52건 분석으로 구조 개선을 제안하고 결정 15건을 합의, 작성·검증 체계로 구현. 구현 전 결정 요청 39건(반영 34건)

## 구조

```
product/    제품 개발 — 서비스 영역별 기여
ax/         AX 전환 — AI로 개발 방식을 바꾼 일
process/    개발 프로세스 — 팀이 일하는 방식을 개선한 일
timeline/   연도별 흐름 (세 축을 시간순으로 연결)
stories/    대화·면접용 짧은 에피소드
data/       월·제품 표면·작업 유형별 커밋 집계 (해시·메시지 없음)
_templates/ 템플릿
```

## 읽는 순서

1. 위 **하이라이트**로 전체 그림을 본다.
2. [stories](stories/)에서 관심 가는 에피소드를 고른다 (한 편에 1~2분).
3. 더 자세한 내용은 에피소드에 연결된 축 문서(product / ax / process)에서 본다.
4. 시간 흐름이 궁금하면 [timeline](timeline/)을 본다.
