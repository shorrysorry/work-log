## 한 줄 요약

채용 담당자가 **공고를 열고 → 지원자를 모으고 → 평가·소통하고 → 데이터를 안전하게 관리**하는 흐름 전반의 프론트엔드를 4년 넘게 만들어 왔습니다.
최근에는 외부 서비스 연동과 데이터 보호 기능처럼 **여러 직군·외부 파트너와 계약을 맞춰야 하는 기능**을 주로 맡고 있습니다.

## 1. 채용 운영 — 공고와 채용 사이트

### 채용 사이트 빌더 (2022-09 ~ 10) — 입사 후 첫 기능

고객사가 자기 채용 사이트를 **헤더·배너·섹션·푸터 같은 블록을 조합해** 꾸미는 편집 기능을 만들었습니다 (커밋 약 66개).

### 포지션 모집 상태 · 접수 예약 · 전체 포지션 둘러보기 (2026-08 ~ 10)

채용 공고(포지션)의 모집 상태와 접수 기간 예약, 전체 포지션을 한 화면에서 훑어보는 기능을 만든 **대형 작업**입니다 (커밋 약 385개).

- 다른 FE 개발자와 화면 단위로 작업을 나눴고, 둘러보기 행을 제외한 나머지 화면을 맡았습니다.
- 마감 기준이 바뀌면서 공개 채용 사이트 쪽 변경은 리뷰로 참여했고, 별도로 운영되는 채용 사이트 한 곳의 마감 표시는 직접 맞췄습니다.
- 개발 중 내려진 결정과 리뷰 결과를 작업 문서에 계속 반영했습니다 → [개발 프로세스](../process/#3-작업-문서와-구현의-동기화-2026-10--11)

### 포지션 사용자 정의 보기 (2026-06)

채용 담당자가 포지션 목록을 **자기 기준으로 저장해 두고 탭으로 전환**하는 보기 기능 — 보기 탭바, 보관함, 이름·색상 지정, 사이드 메뉴 연결 (커밋 약 100개).

## 2. 지원자 관리 — 목록·상세·칸반·일괄 작업

### 칸반 즉시 반영 정비 — 범용 구조를 걷어내고 동작별로 고정 (2026-08)

지원자를 추가·삭제하거나 지원서·일정을 고치면 **칸반 보드의 카드와 개수가 바로 맞아야** 했습니다.

- 처음에는 동기화를 한곳에서 조율하는 **범용 구조**를 만들었다가, 며칠 뒤 **모두 걷어내고** 동작마다 업데이트를 명시적으로 연결하는 방식으로 바꿨습니다.
- 지원자 추가·삭제, 다른 공고 이동, 지원서 수정, 일정 조율·확정·삭제, 메시지 개수 등 **기존 동작을 테스트로 먼저 고정**했습니다 (테스트·고정 커밋 24개).
- 그 위에서 즉시 반영되지 않던 경우만 골라 고쳤고, 바로 고치지 않은 불일치는 기록으로 남겼습니다 (전체 커밋 약 62개).

### 일괄 작업 확장·리팩토링 (2025-11 ~ 2026-07)

여러 지원자를 골라 한 번에 처리하는 일괄 작업의 종류를 늘리고, **중복 요청 차단·선택 가능 인원 정책·권한 표시**를 정리한 뒤 구조를 리팩토링했습니다.

### 서류 요청 개선 (2026-05)

지원자에게 추가 서류를 요청하고 받는 흐름을 백오피스와 지원자 메시징 양쪽에서 개선했습니다 (커밋 약 139개).

### 지원자 상세 뷰 (2026-07)

지원자 상세의 **기본 보기 설정**, 흩어져 있던 헤더 액션을 하나의 메뉴로 통합, 첨부 파일을 PDF와 일반 파일로 나누고 **화면 안에서 바로 보는 PDF 뷰어**를 만들었습니다 (커밋 약 35개).

### 일정·면접 관리 (2023 ~ 2026)

그룹 면접 일정(2024-10), 일정 관리 개선(2025-03, 커밋 약 69개), 캘린더 종일 일정 표시(2026-11), 그리고 여러 화면이 함께 쓰는 **날짜·시간 범위 선택기**(2026-11, 커밋 약 39개)를 만들었습니다.

### 그 밖에

지원자 첨부·평가표 개선(2023), 지원자 데이터 일괄 업로드와 오류 안내(2024-11), 지원서 항목 개선(2025-06) 등.

## 3. 외부 서비스 연동 — 검사·평가 서비스

채용 과정에서 쓰는 외부 검사·평가 서비스를 제품 안에서 **요청하고, 진행 상태를 보고, 결과를 받아보게** 하는 연동을 여러 건 맡았습니다.

| 시기 | 연동 | 규모(약) |
|---|---|---|
| 2024-08 ~ 10 | 외부 검사·평판 조회·코딩 테스트 서비스 등 여러 곳 | 커밋 115+ |
| 2025-09 | 코딩 테스트 서비스 | 커밋 20 |
| 2026-03 | AI 서류 평가 서비스 (단건·일괄 요청, 결과 파일함) | 커밋 60 |
| 2026-11 | 외부 검사 기관 (검사 예약·응시자 관리·결과 열람, 지원자 자료함 통합) | 커밋 120+ |

- 가장 최근 연동에서는 구현 전에 기획·디자인·API 계약을 대조해 **결정 요청 32건**을 먼저 올렸고, 그중 27건이 기획 문서에 반영된 뒤 구현했습니다 → [개발 프로세스](../process/#2-구현-전-스펙-리뷰--결정-요청을-티켓으로-2026-11)
- 외부 서비스마다 다른 오류 응답을 팀 공통 오류 처리 규약 안에서 다루도록 맞췄습니다.

## 4. 데이터 보호·계정 관리

고객사의 보안·관리 요구에서 출발한 기능들을 **설계 검토부터** 맡았습니다.

- **사용자 비활성화** (2026-04, 커밋 약 72개) — 계정 비활성화 기능과 관련 화면 전반
- **로그 관리** (2026-02) — 비활성화와 함께 고객사 요청으로 설계 검토부터 진행한 기록 관리 기능
- **감사 로그 내보내기 사유** (2026-10) — 데이터를 내보내거나 인쇄할 때 사유를 남기게 하는 기능
- **데이터 보관 기간 설정** (2026-02), 다운로드 권한 정리
- **SSO 로그인** (2024-06, 커밋 약 26개)

## 5. 외부 지원자 수집 — 데스크톱 앱·브라우저 확장

여러 외부 채용 플랫폼의 지원자 정보를 제품으로 가져오는 **Electron 데스크톱 앱과 브라우저 확장**을 맡았습니다.

- 플랫폼마다 다른 화면·데이터 구조에 맞춰 **수집 로직을 플랫폼별로 안정화**하고, 수집 실패를 사용자에게 구분해 알리도록 오류 처리를 보강했습니다.
- 첨부 링크 누락 제보는 제보된 플랫폼을 포함한 4개 플랫폼·5개 수집 경로를 함께 고치고, 링크 검증을 강화했으며, 수집 단계를 진행률 루프 안으로 옮겨 **사용자의 취소가 즉시 반영**되도록 했습니다 → [에피소드](../stories/2026-11-attachment-collection.md)
- 지원자 일괄 다운로드 확장을 인수인계받아 오류 기록과 방어 코드를 추가했습니다.

## 일하는 방식에서 드러난 점

- **바꾸기 전에 고정한다.** 큰 리팩토링은 기존 동작을 테스트로 먼저 잡고 시작했다.
- **계약부터 맞춘다.** 외부 연동은 구현 전에 기획·디자인·API 계약의 빈틈을 먼저 질문으로 정리했다.
- **넓게 맡는다.** 웹 앱, 공개 채용 사이트, 브라우저 확장, 데스크톱 앱까지 제품 표면 전반을 다뤘다.
