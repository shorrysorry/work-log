# 구현 전에 질문 32개를 먼저 던진 연동

- 시기: 2026-11
- 유형: 협업 · 리스크 관리
- 관련 축: [product](../product/#3-외부-서비스-연동--검사평가-서비스) / [process](../process/#2-구현-전-스펙-리뷰--결정-요청을-티켓으로-2026-11)

**상황** — 외부 검사 기관과의 연동 기능을 맡았습니다. 기획 문서, 디자인, API 계약이 각각 따로 만들어져 서로 어긋나는 부분이 있었습니다.

**내가 한 일** — 구현에 들어가기 전에 세 문서를 대조해 빠지거나 어긋난 부분을 **결정 요청 티켓 32건**으로 올렸습니다.
티켓마다 판단할 직군(기획·디자인·개발)과 **승인을 막는 항목인지**를 표시해 무엇부터 정해야 하는지 드러냈습니다 (승인 차단 6건).
결정이 나면 기획 문서에 반영해 구현 기준을 한곳에 모았습니다.

**결과** — 32건 중 27건이 기획 문서에 반영된 상태로 구현을 진행했습니다.
같은 방식을 이후 캘린더 개선 기능(7건, 전부 반영)에도 적용했습니다.

**한 줄 요약** — "구현 중에 재작업이 될 질문을 착수 전에 티켓으로 모았고, 누가 결정해야 하는지까지 표시해 빠르게 닫았습니다."
