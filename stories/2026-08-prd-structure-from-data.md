# "PRD가 불편하다"를 데이터로 바꾸기

- 시기: 2026-08 ~ 09
- 유형: 개선 제안 · 협업
- 관련 축: [process](../process/#1-prd-구조-개선--제안에서-체계-구현까지-2026-08--09) / [ax](../ax/#3-ai로-스펙-품질을-검증하는-체계-2026-09)

**상황** — 프론트엔드 개발자가 구현을 시작하고 완료를 판정하는 데 필요한 정보가 기획 문서, 디자인 파일, 개발자 판단 사이에 흩어져 있었습니다.
화면 상태나 오류 처리 같은 정보가 빠지기 쉬웠고, 착수 후 질문이 몰렸습니다.

**내가 한 일** — 불편을 말하기 전에 기획 문서 데이터베이스 전체 52건을 분석하고, 진행 단계가 다른 실제 문서 10건을 표본으로 검토했습니다.
문제를 유형별로 정리하고, 문서를 길게 만드는 대신 "공통 구현 코어 + 해당될 때만 펼치는 모듈"로 바꾸는 개선안을 냈습니다.
팀과 합의한 내용은 결정 15건으로 배경·이유와 함께 기록해 위클리에서 공유했고,
그 구조를 작성 규칙·검증 스크립트·점검 게이트로 만들어 AI 에이전트가 지키도록 했습니다.

**결과** — 합의된 구조로 대형 기능의 통합 PRD를 작성해 실제 개발에 적용했습니다.

**한 줄 요약** — "프로세스를 바꾸자고 하기 전에 문서 52건을 분석해 문제를 보여줬고, 합의한 규칙은 사람의 기억이 아니라 검증 도구에 넣었습니다."
